# nameplate-maker
행사용 양면 명패 자동 생성기

CSV·TSV 인코딩 지원과 회귀검증 방법: [tests/README.md](tests/README.md)

## 좌석배치 연동 안전 가져오기

좌석배치기에서 명단을 보내면 수신 인원과 기존 인원을 확인한 뒤 `백업 후 가져오기`를 선택합니다. 취소하면 기존 명단을 유지합니다. 이전 명단·로고·디자인은 브라우저에 1회분 백업되며 페이지 하단의 백업 내려받기 버튼에서 JSON을 저장할 수 있습니다. 내려받은 파일은 기존 프로젝트 JSON 가져오기로 복구합니다.

다른 창에서 저장한 프로젝트를 오래된 창이 덮어쓰지 않도록 보호합니다. 관련 안내가 나오면 현재 작업을 JSON으로 저장하고 새로고침해 주세요. 브라우저 데이터 삭제는 백업도 삭제하므로 중요한 행사는 파일로 별도 보관해야 합니다.

허용 origin과 opener 확인, 전송 ID·인원·문자열 검증 및 중복 수신 방지를 적용합니다. 회귀테스트: `node --test tests/*.test.mjs`.

저장된 프로젝트 JSON이 손상된 경우 자동저장을 중지하여 원본을 보호합니다. `작업 저장`은 이때 복구용 원본을 내려받습니다. 유효한 프로젝트 JSON을 불러오면 기존 원본을 먼저 백업한 후 다시 저장할 수 있습니다.

## 행사 변경분과 실제 출력 확인 (MACH)

PRIME의 연결 버튼으로 연 명패 창에서 `명패 변경분 확인`을 확인하고 `선택한 변경 반영`을 누릅니다. 같은 PC·브라우저에서 사용자가 연 창 사이의 명시적 전달입니다. 전체 명단을 자동 교체하거나 실시간 동기화하지 않습니다. 파일로 받은 경우 상단 `변경분 JSON 가져오기`를 사용합니다. 행사와 참석자 식별자를 비교하며, 이름이 같아도 다른 ID는 합치지 않습니다.

- 기존 공통 디자인·로고와 개인별 이름·소속·직책 표시를 보존합니다. 별도 표시와 받은 변경이 충돌하면 받은 내용 적용 / 현재 표시 유지 / 직접 정정을 선택합니다. 유지한 내용은 상대 도구에 반영 완료로 표시하지 않습니다.
- `변경된 명패만`에서 개별 선택 → `선택 명패 미리보기` → `선택 명패 인쇄·PDF`를 사용합니다. 명단 순서와 각 페이지의 양면 한 쌍을 그대로 유지합니다. 좌석번호는 기존 명패에 인쇄하지 않으므로 자리만 바뀌면 재출력하지 않습니다.
- 인쇄 준비 시 대상·이름·표시 문구·디자인·로고·렌더링 내용을 출력 작업에 고정합니다. PDF 저장이나 인쇄 창 종료는 완료가 아닙니다. 실물을 확인한 뒤 해당 작업의 `이 작업 출력 완료 확인`을 누릅니다. 작업을 만든 뒤 바꾼 이름은 이전 작업 완료로 확인되지 않습니다.
- 기록 없는 기존 자료는 `출력 여부 미확인`입니다. 실물이 현재 표시와 같음을 확인한 경우에만 `현재 선택 명패를 실물 출력 기준본으로 지정`을 사용합니다. 불참·교체 전 참석자는 새 출력에서 제외하고 별도 회수·폐기 목록으로 남깁니다.
- `출력 상태 전달`은 연결한 PRIME 창으로 확인본을 전달합니다. 전달 완료와 상대 도구의 반영 완료를 구분합니다. 창 연결이 없으면 `출력 상태 JSON 저장`으로 전달할 수 있습니다.

`작업 저장`에는 명단, 디자인, 로고, 연동 기준본, 출력 작업, 출력 확인본, 회수 기록이 포함됩니다. `직전 변경 되돌리기`는 이 명패 앱만 복원합니다. 다른 도구에는 다시 전달·확인이 필요합니다. 중요한 행사는 각 앱의 작업 파일을 별도로 보관하세요. 브라우저 데이터를 지우면 브라우저 안의 백업도 지워집니다. CSV는 행사 ID·출력 이력을 복원하지 않으므로 연결한 행사는 연동 JSON을 사용합니다.

기존 저장 키 `nameplate-maker-project-v27`을 유지합니다. 마이그레이션 전 원본은 `:before-migration`, 변경 적용 전 전체 작업은 `:before-mach`에 보관합니다. 알 수 없는 형식·손상 JSON·다른 탭의 더 최신 저장·백업 또는 저장 실패 시 적용하지 않습니다. 이전 버전 좌석 전달 방식은 연결 행사나 출력 이력이 있는 작업의 전체 교체를 거부합니다. 데이터 스키마를 이해하지 못하는 과거 버전으로 단순 코드 되돌리기를 하기 전에 JSON 파일과 원본 백업을 확보해야 합니다.

검증 명령과 실제 실행 결과는 [tests/MACH-VALIDATION.md](tests/MACH-VALIDATION.md)를 참고하세요.

이번 세 앱 통합 실행 결과는 [MACH 통합 검증 기록](tests/MACH-INTEGRATION-VALIDATION.md)과 [전달 계약](MACH-CONTRACT.md)을 참고하세요.
