별도 깨끗한 clone과 codex/mach-event-changes 브랜치에서 작업했다. 기존 실패는 없었다. 최종 Node 테스트 합계 256개가 통과했다. 공통 계약 테스트 12개는 각 저장소에서 각각 실행되므로 합계에 세 번 포함된다. 기존 테스트를 삭제하거나 조건을 완화하지 않았다. 기존 브라우저 테스트 서버에 새 JS 파일 MIME 지원만 추가했다.

PRIME 도면/좌석 정의는 시작 main과 바이트 단위로 동일하다. MAIN-L/R 48석, HEAD 1석, STAFF 14석, 기존 가구/모니터/곡률/기관 배치 정책을 보존했다. 명패 원본 이미지·로고·템플릿 파일과 원큐 HWP 파일을 수정하지 않았다. 테스트는 격리 Chrome 프로필과 가상 자료를 사용했다.

## 실제 Chrome 실행 결과

- 원큐에서 가상 행사와 네 명 입력 → 실제 연결 창의 handshake → PRIME 미리보기 승인 전 상태 불변 → 선택 반영.
- 일반석 네 자리와 고정석 지정 → 좌석 결과를 원큐에서 확인. 명패 연결 창으로 전달하고 개별 소속 표시와 줄바꿈 디자인 조정.
- PRIME 성공 후 명패 백업/본 저장에 가상 용량 오류 주입 → 명패 원본과 PRIME 성공 상태 보존 → 같은 전달을 다시 확인하고 명패 단계만 재시도. 중복 참석자 없음.
- 네 명의 출력 작업 생성 시 완료 이력은 0건. 별도 사용자 확인 뒤 해당 작업만 완료 처리.
- 직책 정정, 불참, 대리참석, 추가를 함께 발생시킴. 직책만 선택 적용한 시점에 전체 기존 좌석·고정석·미선택 자료 불변 확인.
- 나머지 반영: 불참 자리만 비움, 대리자의 선택한 자리 승계, 신규 참석자 미배정, 무관한 자리와 HEAD 미변경.
- 명패 재수신 후 공통 디자인과 개별 표시 보존. 변경 대상 3명만 선택하여 미리보기 3페이지·양면 6면 확인. 불참·교체 전 명패는 별도 회수 목록 유지.
- 출력 작업 생성 후 이름 수정 → 이전 작업 완료 확인 → 최신 이름은 수정 재출력 필요로 남음.
- 명패 → PRIME → 원큐 실제 창으로 출력/수신 상태를 반환. 수신 기준본과 실제 출력 기준본을 분리해 대조. 원큐 활성 인원 4명, 도구별 반영 상태와 회수/수정 목록 확인.
- 390px·412px·1440px 핵심 화면 가로 넘침 없음. PRIME·명패 변경 확인 대화상자도 390/412px에서 선택·확인 버튼 접근을 확인. 전체 모바일 시나리오를 모든 기기에서 실행했다는 뜻은 아니다.
- 세 앱 각각 기존 작업 파일 저장 → 초기화 → 복원으로 ID·배치·디자인·출력 이력 왕복 확인. 통합 흐름 후 새로고침도 상태 동일.
- 새 PRIME → 실제 변경 전 명패 HTML을 격리 창에 띄운 혼합 버전 테스트: 준비 응답이 없어 확인 불가로 종료, 기존 명패 상태 불변, 성공 오표시 없음. 이 구버전 시험에서는 기존 analytics 요청을 차단했다.
- 최종 새 세 앱 통합 실행: pageerror 0, 외부 네트워크 요청 0, 입력을 포함한 URL/HTTP 본문 요청 0. 정적 앱 파일 요청과 브라우저 내부 postMessage를 구분하여 검사했다.

## 재실행

각 저장소에서 `node --test tests/*.test.mjs`를 실행한다. Playwright/Chrome은 선택 검증 도구이며 운영 의존성을 추가하지 않았다.

세 저장소를 같은 부모 폴더에 둔 뒤 원큐 저장소에서:

```sh
MACH_REPOS_ROOT=/path/to/repos node tests/mach-server.cjs
PLAYWRIGHT_MODULE=/path/to/playwright node tests/browser-mach-integrated.cjs
```

앱별 `tests/browser-mach.mjs`(원큐), `tests/browser-mach.cjs`(PRIME), `tests/mach-browser.cjs`(명패)도 실행한다. 혼합 버전은 변경 전 명패 index.html을 별도 파일로 보관해 `LEGACY_NAMEPLATE_HTML`을 지정하고 원큐의 `tests/browser-mach-old-receiver.cjs`를 실행한다. 운영 확인에는 통합 스크립트의 `MACH_BASE=https://erakeun.github.io`를 사용한다.

## 배포/복구와 한계

수신 기능인 명패 → PRIME → 원큐 순서로 기존 GitHub Pages 주소에 배포한다. 명패·원큐는 main 루트의 기존 Pages 빌드, PRIME은 기존 Actions의 tests → dist 배포를 유지한다. 배포/PR/SHA 결과는 별도 최종 릴리스 기록을 따른다. 이 파일 작성 시점에는 아직 배포 완료로 표기하지 않는다.

복구할 코드는 위 출발 main이다. 코드를 되돌려도 브라우저 데이터가 자동으로 구형으로 복구되는 것은 아니다. 변경 전 앱별 JSON과 브라우저의 before-migration/before-mach 백업을 별도로 보관한 뒤 호환 저장본을 명시적으로 복원한다. 브라우저 데이터 삭제는 내부 백업도 지운다. 원큐 하나의 JSON은 다른 도구의 좌석·디자인을 완전 복원하지 않는다.

실제 프린터, Chrome 외 브라우저, 서로 다른 PC에서의 실제 이동은 미검증이다. 서로 다른 PC에 필요한 앱별 파일 저장·복원 경로는 위 왕복 시험으로 확인했다. 인쇄 창/PDF 생성/afterprint만으로 출력 완료를 지정하지 않는다. 다운로드 PDF와 종이는 자동 갱신되지 않는다. 로그인·서버 DB·실시간 협업·외부 예약/주문 변경은 추가하지 않았다.
